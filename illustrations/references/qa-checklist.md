# Checklist de QA

## Criterios obligatorios

- Formato horizontal 16:9.
- Fondo blanco limpio.
- Aparece Xiaohei.
- Xiaohei ejecuta la acción central, no es un mero adorno.
- No replica composiciones de ejemplos anteriores; inventa una metáfora nueva para el texto actual.
- Se siente absurda, creativa e interesante.
- Limpia y despejada; el sujeto principal no supera aprox. el 60% del lienzo.
- Una imagen explica una sola estructura central.
- Pocas etiquetas manuscritas, cortas y legibles.
- El naranja se usa solo para el flujo o flechas principales.
- El rojo se usa solo para puntos clave, problemas, alertas o resultados.
- El azul se usa solo para notas complementarias, feedback o estado del sistema.

## Señales de fallo

Regenera o edita localmente si aparece cualquiera de estos problemas:

- Título en la esquina superior izquierda ("Errores comunes / Workflow / Arquitectura / Roadmap", etc.).
- Xiaohei parece mascota, sticker de meme o caricatura tierna.
- La imagen parece diapositiva de PPT, material de curso o diagrama formal.
- Demasiados elementos, demasiadas flechas o demasiados nodos.
- El texto se convierte en párrafos explicativos largos.
- El fondo tiene textura de papel, sombras, degradados, tono crema o ruido.
- Capturas reales de UI o interfaces futuristas.
- Errores ortográficos graves o etiquetas ilegibles.
- Escena rígida sin metáfora absurda.
- Composición demasiado parecida a algún ejemplo de `assets/examples/`.

## Cómo iterar

- **Muy común / aburrida**: haz que Xiaohei sea el sujeto de la acción e introduce una metáfora extraña pero coherente.
- **Muy compleja**: elimina nodos y deja una sola acción con 3-5 etiquetas breves.
- **Muy tierna**: enfatiza *deadpan*, *blank serious expression*, *not cute*, *not mascot*.
- **Muy estilo PPT**: quita títulos, recuadros, cuadrículas ordenadas y exceso de flechas; pásalo a escena dibujada a mano.
- **Muy parecida a un ejemplo previo**: conserva la idea central, pero cambia el objeto principal y la acción de Xiaohei.
- **Texto con errores**: prioriza edición local; si hay muchos fallos, regenera reduciendo la cantidad de etiquetas.

## Criterio de entrega

Una buena ilustración hace que el lector piense primero "qué raro está esto" y en menos de 1 segundo entienda la estructura.

Si a primera vista parece la página de un tutorial y no un boceto absurdo sobre papel en blanco, no aprueba.
